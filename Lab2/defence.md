# Шпаргалка до захисту — Лабораторна робота №2 (ООП)

## 1. Варіант завдання (номер у списку Ж = 26)

| Параметр | Формула | Значення для Ж = 26 | Реалізація у коді |
|---|---|---|---|
| Масив фігур | `Ж mod 3` (`0` — динам., інакше — стат.) | `26 mod 3 = 2` → **статичний**, `N = Ж + 100 = 126` | `static Shape *pcshape[126]` у `ShapeEditor` |
| «Гумовий» слід | `Ж mod 4` | `26 mod 4 = 2` → **суцільна лінія синього кольору** | `QPen(Qt::blue, 1, Qt::SolidLine)` |
| Ввід прямокутника | `Ж mod 2` | `26 mod 2 = 0` → **по двом протилежним кутам** | `(xstart, ystart)` і `(xend, yend)` |
| Відображення прямокутника | `Ж mod 5`, `Ж mod 6` | `26 mod 5 = 1`, `26 mod 6 = 2` → **чорний контур + блакитне заповнення** | `QPen(Qt::black, 1)` + `QColor(0, 255, 255)` |
| Ввід еліпса | `Ж mod 2` | `26 mod 2 = 0` → **від центру до одного з кутів** | `x1 = 2*xstart - xend`, `y1 = 2*ystart - yend` |
| Відображення еліпса | `Ж mod 5` | `26 mod 5 = 1` → **чорний контур + біле заповнення** | `QPen(Qt::black, 1)` + `Qt::white` |
| Позначка активного режиму | `Ж mod 2` | `26 mod 2 = 0` → **галочка в меню (`OnInitMenuPopup`)** | сигнал `QMenu::aboutToShow` → `OnInitMenuPopup` |

## 2. Загальна ідея роботи програми

Уся програма побудована на **двох ієрархіях класів** і **двох точках поліморфізму**:

1. **Ієрархія фігур (`Shape`)** — описує *як намалювати готову фігуру* (`PointShape`, `LineShape`, `RectShape`, `EllipseShape`). Усі створені фігури зберігаються в одному масиві базових вказівників `Shape *pcshape[126]` і малюються в циклі викликом `pcshape[i]->Show(painter)`.
2. **Ієрархія редакторів (`Editor` → `ShapeEditor`)** — описує *як вводити фігуру мишею* (`PointEditor`, `LineEditor`, `RectEditor`, `EllipseEditor`). У `ShapeObjectsEditor` зберігається один вказівник `ShapeEditor *pse`, який вказує на активний зараз редактор.

**Ланцюжок дій користувача:**
1. Користувач обирає пункт у меню `Об'єкти` (наприклад, `Прямокутник`) → `ShapeObjectsEditor` видаляє старий `pse` і створює `new RectEditor()`.
2. Користувач затискає ЛКМ → `MainWindow::mousePressEvent` → `editor.OnLBdown(x, y)` → запам'ятовується початкова точка `(xstart, ystart)`, вмикається `isDrawing = true`.
3. Користувач рухає мишу → `MainWindow::mouseMoveEvent` → `editor.OnMouseMove(x, y)` оновлює `(xend, yend)` і викликає `update()` → `paintEvent` малює всі збережені фігури + синій «гумовий» слід (`drawRubber`).
4. Користувач відпускає ЛКМ → `MainWindow::mouseReleaseEvent` → `editor.OnLBup(x, y)` вимикає `isDrawing`, створює готовий об'єкт (`new RectShape()`), записує його в `pcshape[]` і викликає `update()`.

## 3. Пояснення коду по кожному файлу

### `CMakeLists.txt`
Конфігурація збірки проєкту:
- Задає стандарт **C++17**.
- Вмикає `CMAKE_AUTOMOC ON` — Qt автоматично генерує код для макросу `Q_OBJECT` (сигнали й слоти в `MainWindow`).
- Знаходить встановлену версію Qt (`Qt6` або `Qt5`, модуль `Widgets`).
- Збирає всі `.h` та `.cpp` файли у виконуваний файл `Lab2` і лінкує бібліотеку `Qt::Widgets`.

### `main.cpp`
Точка входу програми:
- Створює `QApplication app(argc, argv)` — обов'язковий об'єкт Qt, який керує ресурсами та чергою подій.
- Створює і показує головне вікно `MainWindow w; w.show();`.
- Запускає цикл обробки подій `app.exec()` (він слухає кліки миші, перемалювання, меню аж до закриття вікна).

### `shape.h` і `shape.cpp`
Модуль геометричних фігур. Відповідає **тільки за зберігання координат та малювання фігур** (не знає нічого про мишу чи меню).

- **`class Shape`** — перший **абстрактний базовий клас** (містить чисто віртуальний метод `virtual void Show(QPainter &painter) = 0;`, тому створити екземпляр `Shape` напряму не можна).
  - Поля `xs1, ys1, xs2, ys2` мають модифікатор `protected`, щоб бути прихованими зовні (інкапсуляція), але доступними у класах-спадкоємцях.
  - `virtual ~Shape() = default;` — віртуальний деструктор, щоб при `delete pcshape[i]` коректно знищувався саме похідний об'єкт.
  - `Set(x1, y1, x2, y2)` — спільний для всіх фігур метод запису координат.
- **`PointShape::Show`** — ставить чорне перо товщиною 3 px (щоб крапку було добре видно) і малює `painter.drawPoint(xs1, ys1)`.
- **`LineShape::Show`** — чорне перо товщиною 1 px, малює відрізок `painter.drawLine(xs1, ys1, xs2, ys2)`.
- **`RectShape::Show`** — чорний контур `QPen(Qt::black, 1)` і блакитна заливка `QColor(0, 255, 255)`. Через `qMin` і `qAbs` обчислюються лівий верхній кут `(x, y)` та розміри `(w, h)`, щоб прямокутник правильно малювався незалежно від того, у який бік тягнули мишу.
- **`EllipseShape::Show`** — чорний контур `QPen(Qt::black, 1)` і біла заливка `Qt::white`, малює `painter.drawEllipse(x, y, w, h)` у межах охоплюючого прямокутника `(xs1, ys1) — (xs2, ys2)`.

---

### `editor.h`
Містить другий **абстрактний базовий клас** — `class Editor`:
- Оголошує 4 чисто віртуальні методи: `OnLBdown`, `OnLBup`, `OnMouseMove`, `OnPaint` та віртуальний деструктор `~Editor()`.
- Фіксує єдиний базовий інтерфейс для будь-якого редактора. За вимогою методички `OnInitMenuPopup` сюди **не додається**, а виноситься у похідний клас `ShapeEditor`.

---

### `shape_editor.h` і `shape_editor.cpp`
Модуль логіки введення та керування фігурами.

#### 1. `class ShapeEditor : public Editor`
Реалізує спільну логіку для всіх редакторів фігур:
- **Статичний масив фігур**:
  ```cpp
  static constexpr int MAX_SHAPES = 126;
  static Shape *pcshape[MAX_SHAPES];
  static int shapeCount;
  ```
  Масив зроблено `static`, тому що при перемиканні інструмента старий об'єкт `pse` видаляється і створюється новий, а вже намальовані фігури повинні залишатися спільними для всіх редакторів.
- **`addShape(Shape *shape)`** — додає фігуру в `pcshape`, якщо `shapeCount < 126`; інакше видаляє `shape`, щоб не вийти за межі масиву і не створити витік пам'яті.
- **`OnLBdown` / `OnMouseMove` / `OnLBup`** — базова реалізація для «розтягуваних» фігур: на натисканні зберігає `(xstart, ystart)` і ставить `isDrawing = true`, при русі оновлює `(xend, yend)`, при відпусканні ставить `isDrawing = false`.
- **`OnPaint(QPainter &painter)`** — викликає `paintShapes(painter)` (у циклі поліморфно викликає `pcshape[i]->Show(painter)` для всіх збережених фігур), а якщо зараз триває малювання (`isDrawing == true`), зверху викликає віртуальний метод `drawRubber(painter)`.
- **`OnInitMenuPopup(QMenu *menu)`** — додатковий віртуальний метод для позначки пункту меню. У базовому класі знімає галочки з усіх пунктів.
- **`clearShapes()`** — у циклі звільняє пам'ять (`delete pcshape[i]`), викликається при завершенні роботи програми.

#### 2. Чотири конкретні редактори (спадкоємці `ShapeEditor`)
- **`PointEditor`** — перевизначає `OnLBdown`: одразу на кліку створює `new PointShape()` і додає в `pcshape[]`. `OnMouseMove` і `OnLBup` порожні, бо крапці не потрібен гумовий слід. У `OnInitMenuPopup` ставить галочку біля `"Крапка"`.
- **`LineEditor`** — успадковує `OnLBdown` і `OnMouseMove` від `ShapeEditor`. У `drawRubber` малює синю суцільну лінію. У `OnLBup` створює `new LineShape()`. У `OnInitMenuPopup` позначає `"Лінія"`.
- **`RectEditor`** — у `drawRubber` малює синій контур прямокутника без заливки (`Qt::NoBrush`). У `OnLBup` створює `new RectShape()` по двох протилежних кутах `(xstart, ystart)` і `(xend, yend)`. У `OnInitMenuPopup` позначає `"Прямокутник"`.
- **`EllipseEditor`** — ввід **від центру до кута**: початкова точка `(xstart, ystart)` — це центр, а `(xend, yend)` — один із кутів охоплюючого прямокутника. Протилежний кут симетрично обчислюється як:
  ```cpp
  int x1 = 2 * xstart - xend;
  int y1 = 2 * ystart - yend;
  ```
  (оскільки `xstart - (xend - xstart) = 2 * xstart - xend`). У `drawRubber` малює синій контур еліпса без заливки, у `OnLBup` створює `new EllipseShape()` з координатами `(x1, y1, xend, yend)`. У `OnInitMenuPopup` позначає `"Еліпс"`.

#### 3. `class ShapeObjectsEditor`
Клас-інтерфейс (фасад) модуля редагування для головного вікна:
- Зберігає вказівник `ShapeEditor *pse = nullptr;`.
- Методи `StartPointEditor()`, `StartLineEditor()`, `StartRectEditor()`, `StartEllipseEditor()` видаляють попередній редактор (`delete pse`) і створюють потрібний новий.
- Методи `OnLBdown`, `OnLBup`, `OnMouseMove`, `OnPaint`, `OnInitMenuPopup` делегують виклик активному `pse` (поліморфний виклик через базовий вказівник `ShapeEditor*`).
- Деструктор `~ShapeObjectsEditor()` видаляє `pse` та викликає `ShapeEditor::clearShapes()`, гарантуючи відсутність витоків пам'яті.

### `mainwindow.h` і `mainwindow.cpp`
Головне вікно програми (`class MainWindow : public QMainWindow`):
- Містить поле `ShapeObjectsEditor editor;` — головне вікно працює **лише** через цей клас і нічого не знає про конкретні `Shape` чи `RectEditor` (дотримано інкапсуляцію та ієрархію `#include`).
- У конструкторі створюються три меню у потрібному порядку:
  1. `Файл` → `Вихід`.
  2. `Об'єкти` → `Крапка`, `Лінія`, `Прямокутник`, `Еліпс` (усім задано `setCheckable(true)` для галочки).
  3. `Довідка` → `Про програму`.
- Сигнал `QMenu::aboutToShow` меню `Об'єкти` (аналог `WM_INITMENUPOPUP` у WinAPI) підключений до `editor.OnInitMenuPopup(objectsMenu)` — перед кожним відкриттям меню автоматично оновлюється галочка.
- Обробники Qt:
  - `mousePressEvent` — перевіряє ліву кнопку миші та що клік нижче меню (`y >= menuBar()->height()`), викликає `editor.OnLBdown` і `update()`.
  - `mouseMoveEvent` — якщо затиснута ліва кнопка, викликає `editor.OnMouseMove` і `update()`.
  - `mouseReleaseEvent` — при відпусканні лівої кнопки викликає `editor.OnLBup` і `update()`.
  - `paintEvent` — створює `QPainter`, заливає білим робочу область під меню, обмежує область малювання (`setClipRect`), щоб фігури не налізали на меню, і викликає `editor.OnPaint(painter)`.

## 4. Відповіді на контрольні запитання з методички

1. **Що таке поліморфізм?**
   Це здатність об'єктів різних похідних класів по-різному реагувати на однаковий виклик віртуального методу через вказівник або посилання на базовий клас.
   У нашій програмі є 2 приклади:
   - `pcshape[i]->Show(painter)` — кожна фігура сама знає, як себе намалювати;
   - `pse->OnLBdown / OnMouseMove / OnLBup / OnPaint / OnInitMenuPopup` — кожен редактор по-своєму обробляє дії користувача.

2. **Обробку яких повідомлень (подій) потрібно виконувати для вводу об'єктів?**
   - Натискання лівої кнопки миші (`mousePressEvent` → `OnLBdown`).
   - Переміщення курсора миші (`mouseMoveEvent` → `OnMouseMove`).
   - Відпускання лівої кнопки миші (`mouseReleaseEvent` → `OnLBup`).
   - Перемалювання вікна (`paintEvent` → `OnPaint`).
   - Відкриття підменю для позначки активного режиму (`QMenu::aboutToShow` → `OnInitMenuPopup`).

3. **Що таке абстрактний клас і скільки їх у цій програмі?**
   Абстрактний клас — це клас, який містить хоча б одну чисто віртуальну функцію (`= 0`). Екземпляр такого класу створити неможливо, він задає спільний інтерфейс для спадкоємців.
   У цій програмі **2 абстрактні класи**: `Shape` (чисто віртуальний `Show`) і `Editor` (чисто віртуальні `OnLBdown`, `OnLBup`, `OnMouseMove`, `OnPaint`).

4. **Як намалювати лінії та фігури потрібного кольору та стилю?**
   У Qt для цього використовується клас `QPainter`:
   - Контур (колір, товщина, стиль лінії) задається пером `QPen`, наприклад `painter.setPen(QPen(Qt::blue, 1, Qt::SolidLine))`.
   - Заповнення задається пензлем `QBrush`, наприклад `painter.setBrush(QColor(0, 255, 255))`, `Qt::white` або `Qt::NoBrush` (без заливки).
   - Саме малювання виконується методами `drawPoint`, `drawLine`, `drawRect`, `drawEllipse`.

5. **Як відобразити об'єкти у вікні програми?**
   У головному вікні перевизначено метод `paintEvent(QPaintEvent *)`. Коли потрібно оновити зображення, викликається `update()`, Qt запускає `paintEvent`, де створюється `QPainter` і викликається `editor.OnPaint(painter)`. Той проходить по масиву `pcshape[0 .. shapeCount - 1]` і викликає `pcshape[i]->Show(painter)`, а під час вводу ще й малює гумовий слід `drawRubber(painter)`.
